## La sesión venció

**Qué ves:** el agente te dice que se abrió una ventana para entrar al aula.

Entra con Google en esa ventana (te pide el correo, la contraseña y la verificación de nuevo) y pídele al agente que lo intente de nuevo. Si la ventana no aparece, puede haber quedado detrás de otras. Si aun así no la ves, ejecuta:

```bash
npx -y unsada-mcp@latest login
```

Si el aula rechaza una sesión recién creada, bórrala y entra de nuevo:

```bash
npx -y unsada-mcp@latest logout
npx -y unsada-mcp@latest login
```

## Ya hay una ventana de login abierta

**Qué ves:** *"A classroom sign-in window is already open."*

Termina de entrar en la ventana que ya está abierta, o ciérrala, y vuelve a intentarlo. Solo puede haber una a la vez.

## Pasaron cinco minutos sin entrar

**Qué ves:** *"Five minutes passed without the user finishing the sign-in."*

La ventana espera cinco minutos. Ejecuta `npx -y unsada-mcp@latest login` otra vez cuando puedas completar el login.

## No se abre Edge ni Chrome

**Qué ves:** *"Could not open Edge or Chrome to sign in."*

- Instala [Microsoft Edge](https://www.microsoft.com/edge) o [Google Chrome](https://www.google.com/chrome/). En Windows, Edge ya viene instalado.
- Si tienes los dos y quieres elegir, usa `UNSADA_BROWSER=msedge` o `UNSADA_BROWSER=chrome`.
- En Linux, instala el paquete oficial de Chrome o Edge.

## Versión de Node vieja

**Qué ves:** un aviso `EBADENGINE` de npm, o errores apenas arranca el servidor.

Necesitas Node 22 o más nuevo. Compruébalo con `node -v` y, si es más viejo, instala la versión LTS de [nodejs.org](https://nodejs.org/). Después cierra y abre de nuevo la terminal y el cliente.

<Aside>Si usas nvm o varias versiones de Node, el cliente puede estar usando una distinta de la de tu terminal. Prueba poner la ruta completa de `npx` en la configuración.</Aside>

## El cliente no encuentra npx (Windows)

**Qué ves:** el servidor no arranca, con errores como `spawn npx ENOENT`, `Connection closed` o `-32000`.

Algunos clientes no pueden lanzar `npx` directamente en Windows. Usa `cmd /c` delante:

```bash
claude mcp add unsada -s user -- cmd /c npx -y unsada-mcp@latest
```

En la configuración JSON:

```json
{
  "mcpServers": {
    "unsada": { "command": "cmd", "args": ["/c", "npx", "-y", "unsada-mcp@latest"] }
  }
}
```

## El agente no ve las herramientas

- Reinicia el cliente después de cambiar la configuración. En Claude Desktop, ciérralo también desde la bandeja del sistema.
- En Claude Code, `claude mcp list` muestra si el servidor está conectado.
- Revisa que el JSON sea válido: una coma de más basta para que el cliente ignore el archivo.

## No encuentro los archivos descargados

Se guardan dentro de la carpeta desde donde el cliente lanzó el servidor; la respuesta de `unsada_download` trae la ruta completa en `directory`. Con Claude Desktop esa carpeta puede no ser la que esperas: configura `UNSADA_DOWNLOAD_ROOTS` como dice [Descargas](../descargas/).

## No puede leer un archivo

Los `.doc` y `.ppt` viejos, `.zip`, `.rar` y videos no se pueden leer. El agente te pasa el enlace, o se lo puedes pedir con `unsada_download`.

## Una herramienta devuelve datos raros o vacíos

El servidor lee las mismas páginas que ves en el navegador. Si la UNSAdA actualizó Moodle o cambió el diseño, alguna página puede haber dejado de entenderse. Abre un [issue en GitHub](https://github.com/EmilioGiordano/unsada-mcp/issues) con lo que pediste y lo que devolvió, sin pegar datos personales.
