El aula usa Moodle 3.2, sin servicio para apps móviles, y se entra con Google. Por eso no hay usuario ni contraseña que cargar: el servidor usa tu propio navegador.

<Steps>

1. Ejecuta el comando de login en una terminal:

   ```bash
   npx -y unsada-mcp login
   ```

2. Se abre una ventana pequeña del navegador en modo incógnito, directo en la pantalla de Google. En Windows prueba primero con **Edge** y después con Chrome; en macOS y Linux, al revés.

3. Entras con tu correo, tu contraseña y la verificación en dos pasos, si la tienes. Cuando el aula te reconoce, la ventana se cierra sola y la terminal dice:

   ```
   Listo: sesión iniciada. Ya podés usar unsada-mcp desde tu cliente MCP.
   ```

</Steps>

Tienes cinco minutos para completar el login. Si cierras la ventana antes, no pasa nada: vuelve a ejecutar el comando.

## Después del primer login

- **No hace falta repetirlo.** Mientras el servidor está corriendo, le avisa al aula cada 10 minutos que la sesión sigue en uso.
- **Si la sesión vence**, el servidor vuelve a abrir la ventana solo cuando tu agente necesita algo. Como la ventana no guarda nada, Google te pide el correo, la contraseña y la verificación otra vez. El agente te pedirá que termines de entrar y lo volverá a intentar.
- **Para cambiar de cuenta**, pídele al agente que vuelva a entrar (usa `unsada_login`) o ejecuta `npx -y unsada-mcp logout` y después `login`.

## Comprobar la sesión

```bash
npx -y unsada-mcp status
```

Te dice si hay una sesión guardada, por ejemplo `Conectado (sesión iniciada el …).`, o `Sin sesión: corré unsada-mcp login.` si tienes que entrar.

## Dónde queda guardada

| Sistema | Carpeta |
|---|---|
| Windows | `%APPDATA%\unsada-mcp` |
| Linux y macOS | `~/.config/unsada-mcp` |

Ahí queda solo la sesión del aula (`session.json`). La ventana de login es de incógnito: Google nunca queda con la sesión abierta en tu computadora. Nada sale de tu computadora. Puedes cambiar la carpeta con `UNSADA_MCP_HOME`.

Las versiones hasta la 0.3.0 guardaban ahí un perfil del navegador con tu sesión de Google. El servidor lo borra solo la primera vez que arranca o que ejecutas `login` o `logout`.

<Aside type="caution">
  Quien tenga acceso a esa carpeta puede usar tu sesión del aula, como con cualquier navegador con la sesión abierta. Si usas una computadora compartida, ejecuta `npx -y unsada-mcp logout` al terminar: borra la sesión del aula, y Google no queda abierto.

  Eso incluye a tu agente: si puede ejecutar comandos en la terminal, puede leer cualquier archivo de tu usuario, también `session.json`. Configúralo para que te pregunte antes de ejecutarlos, por ejemplo en OpenCode con `"permission": { "bash": "ask" }`.
</Aside>
